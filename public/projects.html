v1.19.0
Changelog
v1.19.02026-08-19
  • SubType option sets are now generated from each code year’s own ruleset instead of transcribed by hand. The transcription was wrong in four places: ZnSys:SZDFHP and Baseboard fall to the ruleset’s else-branch (13 values, default NA) rather than to a sibling’s set, and MiniSplitAC/MiniSplitHP have a real two-value set (Split3Phase / Split1Phase) that wasn’t offered at all
  • The extractor now parses conditional branches instead of merging them, which recovers the fact that AirSys:Type narrows to five types when AirSys:ServesResZn = 1. Recorded in the tables; not yet applied, since ServesResZn is derived by CBECC rather than stored
  • Each year is read from its own install. The 2025 install also ships a “2022” enum file, but that is a backward-compatibility superset — it lists ZnSys EvaporativeCooler, which the real 2022 ruleset does not. Generating 2022 from it would have silently broken the year gating
  • Where the ruleset declares a default it doesn’t actually offer — true of AirSys HV and Exhaust — that now surfaces as no default rather than a guess
v1.18.02026-08-19
  • Added ZnSys:SZDFHP — the zone-level dual-fuel heat pump. Zone-level SZAC and SZHP went in last release; this was its sibling in the same enum, missed
  • Corrected: zone-level heat pumps were built with no supplemental heating coil, on the assumption that zone units never have one. A real PTHP ZnSys in the corpus does, and so does the ruleset’s own PTHP-ResZnSys baseline block. Zone-level SZHP now gets a Resistance backup and SZDFHP a Furnace one
  • The zone-level backup coil is placed after the Fan, which is where the real record has it — the one point where the zone-level child order departs from the air-system build, where it sits before the Fan
  • PTAC, PTHP, MiniSplitHP, WSHP and zone-level SPVHP still get no backup coil, matching the corpus majority for each
  • The air-system type list is now confirmed complete against CBECC’s own dropdown — 14 types, exact match. Zone systems are complete but for VentilationOnly, which is deliberately excluded
v1.17.12026-08-19
  • The code year the file targets is now a badge in the top bar rather than a suffix on the filename, so it’s legible at a glance in every mode. It is read from the file’s RulesetFilename header and is not editable — the code year is a property of the model, and retargeting a file to another cycle is CBECC’s own conversion job
  • The badge turns amber and says why in the two cases that used to pass silently: a header with no recognisable year (the tool falls back to T24-2025 and now admits it), and a year with no Appendix 5.4A/5.4C tables in this build, where occupancy defaults are deliberately left blank
  • Top bar tidied: the title drops the code year (“CBECC .cibd EDITOR”) now that the badge carries it and the tool reads 2022, 2025 and 2028 files, and the redundant “Open .cibd25 file” button is gone — opening a file is Step 1’s job, and Step 1 now drives the file picker directly
v1.17.02026-08-19
  • Fixed data loss: a system whose Type the tool didn’t recognise had no matching entry in the edit form’s Type list, so the select fell to its first option — opening the form to rename a system and saving would silently retype it and rebuild its subcomponents. Unrecognised Types are now preserved exactly, flagged in the list, and pre-selected in the edit form
  • Fixed silent wrong-cycle defaults: T24-2019 files were served the 2025 occupancy list and 2025 Appendix 5.4A numbers while being labelled T24-2019, and the T24-2028 notice claimed auto-fill was disabled when it wasn’t. Numeric defaults are now never borrowed from another code cycle — no table for the file’s year means nothing is written
  • The partial-support notice is now driven by whether tables exist rather than a hardcoded 2028 check, so T24-2019 gets it too, and it names the file’s own year and says which cycle’s vocabulary is on screen when one is borrowed
  • System types are gated on the file’s code year: a 2022 file no longer offers EvaporativeCooler, which is 2025-only. Availability is derived per year, so withdrawals are handled as naturally as additions; a type valid in another cycle is flagged, not rewritten
  • New tools/extract_ruleset_enums.js derives the per-year tables from CBECC’s own Input Data Model dumps and re-checks them, so the tables can’t drift silently when a ruleset updates
v1.16.02026-08-19
  • Added the packaged system types that were missing from the creator: SZDFHP and SZVAVDFHP (dual-fuel heat pumps), SPVAC and SPVHP (single package vertical), and zone-level ZnSys variants of SZAC, SZHP, SPVAC and SPVHP
  • ZnSys SZAC was the notable gap — 35 records across the reference corpus, more than PTHP or MiniSplit, with none of it reachable before
  • Fixed: heat-pump air systems were built without their supplemental heating coil. 627 of 627 SZHP and 17 of 19 SZVAVHP heating coils in the corpus carry HtPumpSuppCoilHtgRef pointing at a sibling CoilHtg; SZHP and SZVAVHP now get a Resistance backup, and the dual-fuel variants a Furnace one
  • Packaged air systems now set AirSeg:Type and wire OACtrl to their supply and return segments, which were previously left blank
  • SubType options are now per-Type rather than one shared list — SPVAC/SPVHP offer only the two packaged options, zone-level units drop CRAC/CRAH, and Furnace, Radiant and EvaporativeCooler get their own vocabularies (Wall/Floor/Room/Other, Embedded/Panel, Standard/Advanced IEC)
  • Changing a system’s Type now drops a SubType the new Type doesn’t allow, instead of leaving an invalid value on the record
v1.15.02026-08-19
  • Exhaust systems: zone-level exhaust fans (ZnSys Type=Exhaust) alongside central exhaust AirSys, each built with the subcomponents its family actually takes
  • Exhaust properties exposed on the system edit form — ExhSysType (General / Laboratory / CommercialKitchen / ParkingGarage), ExhOperMode, and ExhCtrlMthd, with the fan-control list constrained by the selected exhaust type
  • AirSys:SubType exposed, including CRAC / CRAH for computer-room systems, plus the CRAC-only Config field
  • Systems serving a Computer Room space are flagged when SubType isn’t CRAC or CRAH — the baseline ruleset models those zones as CRAC below 800 kW building computer-room power and CRAH at or above it
  • Per-zone DOAS sizing on the Outside Air / DOAS tab: SizeForDOAS, SizeForDOASCtrl, and the low/high design temperatures, flagged outside CBECC’s 50–90 °F warning band, with copy-to-all
  • Fixed: exhaust systems were wired through VentSysRef in places and ExhSysRef in others. ExhSysRef is the field the data model restricts to Type=Exhaust systems; changing an exhaust system’s type no longer clears an unrelated DOAS assignment on the same zone
